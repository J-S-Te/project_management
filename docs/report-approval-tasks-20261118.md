# 报告审批待办与提醒实施记录

目标：报告返工和报告更正均有可发现、可直达的审批待办及默认站内提醒。
沿用用户已明确的审批归属：报告返工和报告更正均由技术总监审批。
保留现有返工、更正的状态与版本规则，不改已签发报告的作废和新修订规则。

## 方案与接口

- 复用交付事件及事务 Outbox，不引入流程引擎或新表。
- 沿用既有 `project.rollback.approve` 与 `project.report.correction.approve` 权限及数据范围。
- 不新增团队负责人审批权限，不修改现有权限目录版本。
- 返工、更正与现场回退提醒在 Outbox 投递时解析技术总监角色；目录失败进入既有重试，不能吞掉提醒。
- 目录遵循平台每页五十人上限；首次投递前在有效租约内冻结受众。
  超过平台单事件五百人上限时按稳定幂等身份拆批，部分失败重试不重新选择受众。
- 历史兄弟申请被系统自动失效时，同一事务也保存其原申请人的结果提醒。
- 通知携带 `target_url=/project_management/approvals?request_id=<申请ID>`。
  使用平台现有 target_url 字段，不改平台通知协议。
- `GET /api/v1/approval-tasks`：需要 `project.read` 和租户/项目范围。
  查询参数 `page`、`page_size`（最大100）、`view=assigned|submitted`（默认assigned）、
  `request_id`（可选；精确详情包含已处理申请，不因已读或已处理自动执行审批）。
- 响应 `{items,total,page,page_size}`；每项包含：
  `id,type,project_id,service_item_id,site,reason,requester_user_id,approver_user_id,`
  `created_at,version,report_status,service_item_status,status,can_decide,decision_comment`。
  `type=REPORT_REWORK|REPORT_CORRECTION|FIELD_ROLLBACK`；
  `status=PENDING|APPROVED|REJECTED|WITHDRAWN`。
- 默认列表仅待处理；assigned只返回当前用户可审批项，submitted只返回本人申请。
  精确详情仅允许原申请人、归属审批人或已授权管理员访问，跨租户/越权均不暴露。
- 新增前端“审批待办”栏目（approvals），技术总监、项目经理和管理员可见；
  团队负责人仅可跟踪本人已有现场回退申请，不增加审批权限。
  铃铛及个人通知中心均能直接进入对应申请；已处理、失效、无权时给明确状态。
- 原页面申请入口保留，分散的审批动作改为进入统一审批页面。
- 提醒失败不冒充成功；审批继续校验当前版本、原申请和异人规则。
