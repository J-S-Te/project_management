## 0. 业务边界

以服务项为交付单元：已审批合同自动激活或手工权威清单补建 → 确认拆解 → 团队/执行人员分配 → 特殊方法复核（适用时）→ 实施计划 → 准备 → 显式现场开始 → 签到/记录/签字 → 结束 → 报告逐级交付。

项目状态、进度、风险从全部有效服务项派生，不可由客户端改写；执行角色只看自己责任链的服务项，但可见项目的总体状态不按可见子集缩水。项目侧保存设备与差旅快照，不涉及金额结算，不证明外部订票或实物设备流转完成。

## 2. 服务项流转及副作用

| 操作 | 前置条件 | 结果 / 副作用 |
| --- | --- | --- |
| 手工建档 | 权威已审批合同及清单、创建权限及角色、租户内合同身份唯一 | 项目+项同事务；项一律待确认/UNCHECKED，快照类别必检能力码，不套自动放行。 |
| 自动激活 | 受验证机器身份、有效输入、受控类别 | 项目+项+激活事件同事务；按策略分组，按合同身份幂等，合同普通版本变化返回既有项目。 |
| 确认拆解 | 范围校验、选中项待确认/待复核/待分配 | 行锁批量更新待分配，特殊方法未批准则 PENDING；无 Temporal 工作流。 |
| 整单调整 | 原有效项全部待确认/待复核；原因、同客户且不同于原合同、`ApprovalPassed=true` 且状态 `approved/active` 的补充合同、完整新清单 | 归档全部原项并替换；补充状态 REQUIRED，新项确认后 NONE；非增量、不适用已执行/已终止项。 |
| 分配 | 待分配；负责人及目标人员档案/平台角色有效 | 保存负责人/经理/工程师与能力结论；能力 CONFLICT 可以保存但不能发布计划。 |
| 撤销团队 / 执行团队 | 待分配、有对应责任人、原因 | 团队撤销清下游；执行撤销保留负责人；清能力结论与选择，事件保留。 |
| 退回拆解 | 待分配、原因 | 待确认，清责任分配/能力结论/特殊复核。 |
| 特殊方法复核 | special=是，PENDING/REJECTED | APPROVED/REJECTED，仅复核结果，不自动推进实施。 |
| 发布计划 | 待分配、经理、PASSED、适用特殊复核 APPROVED、有效人员与有序计划时间 | 待实施，计划/人员快照；独立渗透须完整合规字段。 |
| 准备 | 待实施或实施准备中、有效计划、结构化差旅、可选有效设备 | 实施准备中，本地差旅/设备快照；新编号不等于真实审批完成。 |
| 撤销计划 / 准备 | 待实施 / 实施准备中、原因 | 计划撤销回待分配并清当前计划；准备撤销回待实施仅释放设备；历史保留。 |
| 现场开始 / 记录 | 实施准备中 / 实施中、现场执行权限 | 显式开始变实施中；记录追加事件且不推进状态。 |
| 偏离 / 评审 | 实施中上报、异常处理中评审 | 上报变异常处理中；放行和重测都回实施中，终止变已终止且不可恢复。 |
| 现场结束 | 实施中、证据存在或不完整原因、专项门禁 | 现场实施完成，报告 NONE，不自动 COMPILING。 |
| 回退申请 / 审批 | 现场实施中或未签发的编制/审核态，原因，不同账号审批 | 申请不改状态；批准现场回准备或报告回实施中/NONE，证据保留；申请人可在审批前撤回。 |
| 报告推进 | 现场实施完成、严格下一阶段、当前有效修订、文件及身份分离/专项门禁 | 逐级推进并记人/时间。 |
| 报告更正 | ISSUED/ARCHIVED，原因及不同账号审批 | 批准后旧版 VOID，下一修订 ACTIVE/NONE；重新完成报告链。 |
| 设备归还 | 可访问且不在待确认/待复核/待分配/已终止 | 记录归还时间释放占用，不删除历史。 |

建项身份为租户 + 稳定合同 ID，历史空 ID 回退合同号；合同版本只用于展示、审计和权威清单一致性校验。迁移 `000033` 同时检查身份键及合同号重复，发现存量同合同多项目时失败关闭，必须先经业务确认，不能靠迁移自动选留项目。

拆解确认清补充标记不等于再次核实合同正式主从关联或自动等待合同回写；范围差异通知也不是跨系统审批实例。

## 3. 项目派生、指标与读取限制

优先级：supplement_status=REQUIRED → 补充协议处理中；无项 → 存储状态/待拆解确认；全部终止 → 已终止；否则取非终止项最低阶段。

阶段 rank：待确认/待复核=0、待分配=1、待实施=2、实施准备中=3、实施中=4、异常处理中=5、现场完成/NONE=6、报告编制/审核/签发=7、归档=8。未知服务项状态保守 rank=0 并有未知状态指标。

进度 = rank 总和 / (8 × 非终止项数) × 100；全部终止为 **0**。风险包括异常/终止项目和任何含终止项的项目；UI 风险卡还结合已加载超期提示，辅助读取失败不能证明没有风险。已完成计数只按派生状态已完成。

普通工作区列表/卡片、独立分页监控与待新建合同统计不是同一加载口径。实时监控不含已完成，保留已终止；事件仓储最近最多 500 条，详情摘要更少，不称“完整历史”。当前报告 UI 按父项目阶段筛选，先完成服务项在父项目早期阶段可能暂不出现在报告列表。

## 4. 资源、配置与外部链路

- 人员候选来自启用 PERSON 档案、ACTIVE 平台身份与关联用户，并校验所需角色；人员不受日期有效期限制，不能沿用旧“过期人员不可指派”描述。
- 独立渗透项要求 PENETRATION_TEST；普通执行分配能力结论不等于全员排期已验证。内嵌专项另有人员排期、计划包含授权有效期、文本范围包含与开始时复核。
- 设备检定按日期；占用保存校验为闭区间，相邻共享结束/开始日冲突。选择器预约提示采用不同过滤，提示不是最终判定；当前在位是本地预约推导。实施准备事务会锁设备主数据并更新 `pm_equipment_reservation` 逐日预约，迁移 `000031` 的租户/设备/日期主键阻止并发重复占用；归还、撤销和删除同步核验/释放预约。已有历史计划及迁移后的现场数据仍需独立对账。
- 主计划 UI 的现场计划通过 `site_plan` 随原有版本、时间和人员清单一并提交，按服务项回显；切换到无计划项时清空上一项草稿。现场计划沿用可空、最多 5000 字的接口契约，历史漏传的文本不能自动恢复。独立渗透合规字段没有内嵌专项同等包含性校验，负责人仍需人工确认。
- 自动激活消费拆解策略/类别/覆盖规则；手工创建和拆解调整也从同一启用检测类别域归一化并写入必检能力码，后续分配只能追加，不能缩减已持久化基线。配置修改不回填旧服务项。覆盖条件不支持 CRM 行业/标签。
- 三类 CSV 在确认时重新校验并逐行保存，可部分成功；预检先上传网关，类别空库读取可能写默认类别，不是绝对零副作用。
- 字段权限仅 hidden，多角色任一命中隐藏；不支持 view/edit 授权。标准方法评估只是人工登记影响与归档台账，不自动改项目/模板。
- 现场文件、签字及报告通过文件网关回执与证据引用；支持账号隔离离线队列和操作键幂等。不承诺 EXIF、防伪定位、数字证书签名或病毒扫描在项目代码中实现。
- 通知进入持久化 Outbox，消费者有租约、重试及死信；主动作成功不等于提醒送达，派生规则失败不回滚已提交主动作。
- SLA 独立消费者已在源码及统一生产 Compose 定义，明确扫描租户、默认 15m；按 status_changed_at 整小时计算，超过时限才超期，计划逾期另算。不是“无定时扫描”。
- API 未装配业务 Temporal Worker；独立 Worker 未注册业务 Workflow/Activity。迁移检查影响 readyz，healthz 成功不等于业务就绪；目标环境配置、依赖与许可本次未验收。

-- Q19：映射表外的服务项状态（这些会把项目状态拖回「待拆解确认」）

ORDER BY updated_at;

SELECT report_status, COUNT(*) FROM pm_service_item GROUP BY report_status;

SELECT p.id, p.status AS stored_status,
       COUNT(i.id) AS item_count,
       SUM(i.status = '已终止') AS terminated_count
FROM pm_project p LEFT JOIN pm_service_item i ON i.project_id = p.id AND i.tenant_id = p.tenant_id
